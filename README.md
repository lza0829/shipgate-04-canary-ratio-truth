# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账

- 前端 http://127.0.0.1:6800
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

```bash
docker compose up -d --build
```

## 金丝雀比例真源（物化臂）

- **唯一真源**：`releases.canary_ratio` 物化列。发版单比例列、总览分布格、对账真源列、
  实例流量暗示、健康页、审计改比例记录全部同读此列，不另立口径。
- **改比例唯一写口**：`POST /api/发版单/{id}/金丝雀比例`，字段更新与审计同事务提交；
  仅在途单（待入闸/已入闸/晋升中）可改，已放行/回滚/关闭单比例冻结。
- **放行写口**：`POST /api/发版单/{id}/晋升` 在同一写事务里把放行当下的真源比例快照进
  `promote_events.canary_ratio`（事件仅作附件），与状态推进同笔，杜绝双写。
- **写并发**：每个请求一个连接、`BEGIN IMMEDIATE` 立即提锁 + WAL + busy_timeout，
  改比例与放行撞车时库层串行，先到先提交，后到读到新值。
- **对账**：按晋升事件附件重放出"回放比例"与真源对读，结论四态——
  一致 / 待下次快照（事件后有改比例审计支撑）/ 脏比例（无审计支撑）/ 未放行。
  定序用同库自增 id（秒级时间戳会丢同秒比较）。
- **纠偏**：`POST /api/对账/金丝雀纠偏` 只把脏事件附件改回真源，真源字段绝不被回改；
  "待下次快照"是合法在途状态，禁止纠偏。
- 测试夹具：`backend/tests/test_canary_source_of_truth.py`
  （先改后放、先放后改、并发双写、半截脏比例、冻结拒写、各面同源）。
